# Context, Decision, Knowledge, SOP

AI Native 운영에서 가장 자주 발생하는 문제는 **아이디어, 현재 상태, 결정, 검증된 지식이 한 문서나 한 대화에 섞이는 것**이다.

이를 다음처럼 구분한다.

## Context

현재 상태와 제약, 아직 검증 중인 가설을 담는다.

예:
- 현재 어떤 기능이 느리다.
- 고객문의가 여러 채널로 흩어져 있다.
- 특정 자동화가 아직 검증되지 않았다.

Context는 바뀔 수 있다.

## Decision

무엇을 선택했고 왜 선택했는지 기록한다.

예:
- 문의의 단일 진입점을 정한다.
- 특정 도구를 기본 실행자로 사용한다.
- 고객 발송 전에는 사람 승인을 유지한다.

Decision은 단순 메모보다 강한 운영 기준이다.

## Knowledge

실행과 Evidence를 통해 반복 사용 가능한 수준으로 검증된 사실과 교훈이다.

예:
- 특정 형태의 입력 누락이 반복 오류를 만든다.
- 특정 Workflow가 재작업을 줄였다.
- 어떤 조건에서는 기존 방법이 실패한다.

한 번 성공했다고 곧바로 Best Practice로 승격하지 않는다.

## SOP / Workflow

Decision과 Knowledge를 실제 반복 행동으로 바꾼다.

```text
Context
  ↓
Decision
  ↓
Execution
  ↓
Evidence
  ↓
Knowledge
  ↓
SOP / Workflow 개선
```

## 핵심 원칙

- 대화에서 나온 아이디어를 자동으로 회사 정책으로 만들지 않는다.
- 현재 상태가 바뀌었다고 과거 Decision을 조용히 덮어쓰지 않는다.
- 검증되지 않은 성공 사례를 전사 규칙으로 일반화하지 않는다.
- 실행자가 다음에 무엇을 읽어야 하는지 연결한다.
